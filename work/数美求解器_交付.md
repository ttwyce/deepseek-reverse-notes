# 数美 spatial_select 点选验证码求解器 —— 交付说明

## 一、成果

纯 Python 复刻数美「空间点选」验证码全流程，**不依赖浏览器、不渲染面板**，端到端成功率 100%（10/10、8/8 两轮实测），单次求解平均 **3.8 秒**。

```
register 拿题 → 下载图片 → 分色连通域识别目标物体
   → DES 加密答案 → JSONP verify → 拿到 rid（PASS）
```

## 二、协议逆向结论

### 1. 组织参数
| 项 | 值 |
|---|---|
| organization | `P9usCUBauxft8eAmUXaZ` |
| appId | `default` |
| model | `spatial_select`（不给则默认滑块） |
| 静态域名 | `castatic.fengkongcloud.cn` |
| 接口域名 | `captcha1.fengkongcloud.cn` |

### 2. 接口
| 接口 | 方法 | 说明 |
|---|---|---|
| `/ca/v1/conf` | GET + JSONP | 取 SDK 版本与资源地址 |
| `/ca/v1/register` | GET + JSONP | 拿题，**无需任何指纹/cookie** |
| `/ca/v2/fverify` | GET + JSONP | 提交答案 |
| `/ca/v1/log` | POST | 明文 JSON 埋点 |

register 响应 `detail`：`{bg, bg_width:600, bg_height:300, k, l:8, order:["点击图中最小的…"], rid}`。
图片是静态 JPG，直接 `GET https://castatic.fengkongcloud.cn<bg>` 即可。

### 3. 加密（关键）
`getEncryptContent(value, salt)` 等价于：

```python
base64( DES-ECB(key=salt 的 8 字节 ASCII, data=UTF8(value) 补 \0 到 8 的倍数) )
```

- 已用 195 组向量（13 salt × 15 值）与 SDK 原生实现逐字节比对，**全部一致**。
- 明文已是 8 的倍数时**不追加整块**；空串直接返回空串。
- 硬编码 salt（即 DES key）：`e1024477`(selectData) `803d9d10`(mouseData) `e6c8d743`(耗时) `d809f47c`(宽) `210a5a6d`(高) `3ae79dfa`(appId) `fa1b1f22`(channel) `10c0600a`(lang) `53cda785`(safeParams) `f2858cfa` `df29aa2d` `9728245c` `24fd4665`。

### 4. verify 请求体
全部字段在 **query** 里（JSONP GET），参数顺序随机、服务端不校验：

| 字段 | 含义 |
|---|---|
| `organization` | 组织 ID |
| `vf` / `ri` / `cx` / `is` | appId / channel / lang / 安全参数，均 DES 加密 |
| `rid` | register 返回的题目 ID |
| `rversion` / `sdkver` / `protocol` / `ostype` | `1.0.4` / `1.1.3` / `210` / `web` |
| `pe` | `selectData` = `[[xRatio, yRatio, 时间戳ms], ...]`，加密 |
| `yc` | `mouseData`（与 selectData 同构），加密 |
| `xt` | `endTime - startTime`（800~20000 随机），加密 |
| `qf` / `qs` | 显示宽高 294 / 147，加密 |
| `pr` / `vn` / `kh` | console / 反调试结果 / 常数，加密 |
| `captchaUuid` | 19 位：`YYYYMMDDHHmmss` + 随机串 |

成功判据：`code == 1100` 且 `riskLevel == "PASS"`。

### 5. 关键约束（决定策略）
- **verify 一次性**：同一 rid 只有第一次提交有效，失败后该 rid 作废。因此不能暴力试候选。
- **同一 captchaUuid 不能连续 register**：会被判为脚本，后续 verify 一律 REJECT。
- **正确答案 = 所有「该颜色 + 该形状」物体中面积最小的那个**，不是「该颜色中面积最小的」。

## 三、图像识别

数美 spatial_select 只用 **4 种颜色**（50 张图统计：蓝 9 / 红 14 / 黄 16 / 绿 11，无橙青紫粉），
色相中心：**红 0°、黄 38°、绿 125°、蓝 208°**。

算法（`tools/sm_cv4.py`）：

1. HSV 阈值 `S≥0.35, V≥0.10` 得高饱和掩码；
2. **逐像素**归到最近的 4 个色相中心（含 360° 环绕）→ 得到 4 张单色掩码。
   4 个中心间距 38~152°，同一物体亮面暗面不会被分到两桶，**不会撕裂**；不同颜色粘连则天然断开；
3. 每张单色掩码做 `closing(5) + opening(3)` + 连通域标记，面积 ≥250 才计为物体；
4. 每个物体算 s*v 加权圆均值色相、面积、bbox、`extent`、`aspect`、`tb` 等几何特征；
5. 按题目颜色过滤，取**面积最小**者，用 bbox 中心作为点击点。

正常图固定 6 个物体；分色连通域解决了「不同颜色物体垂直粘连被合并成一个」的漏检问题。

单次识别准确率约 35%~65%（题目形状歧义时较低），**靠多次换题重试把成功率拉到 100%**。

## 四、求解器用法

```python
from shumei_solver import solve

r = solve(batch=4, rounds=3)
# {'ok': True, 'rid': '...', 'uuid': '...', 'attempts': 2, 'elapsed': 2.5, 'order': '点击图中最小的红色长方体'}
```

- `batch`：每轮并发拿题数（每个独立 captchaUuid）
- `rounds`：最多几轮；总尝试上限 `batch × rounds`
- 策略：**多 uuid 并发拿题 + 串行提交**，第一个 PASS 即返回

命令行自测：

```powershell
.venv\Scripts\python.exe tools\shumei_solver.py --n 10 --batch 4 --rounds 3
```

实测：`10/10 PASS`，平均 3.81 秒，最慢 10.9 秒。

| 接口 | 加密 | 关键字段 |

| `/api/v0/users/mfa/create_verification_code` | **明文** | `mfa_session_id, shumei_verification, shumei_device_id, hcaptcha_token, turnstile_token` |

## 七、反混淆方法（可复用于数美其他版本）

SDK 是 obfuscator.io 产物：`_0x127b()` 返回字符串数组，`_0x3634(i)` 就是 `arr[i - 431]`（**无解密运算**），
外加一个旋转 IIFE 按校验和旋转数组。

`tools/sm_strtab.py` 在浏览器里只执行「header（数组函数 + 解码函数 + 旋转 IIFE）」导出全表；
`tools/sm_deob.py` 收集 566 个解码器别名，替换 5293 处调用，得到可读 SDK。

> 数美会随 SDK 小版本更换 DES key 与参数名（v1.0.4-148…210），换版本需重新跑一遍上述两步。

## 八、受信设备免 MFA 登录（已跑通，2026-10-26）

目标：注册一次受信设备后，后续登录只需「密码 + 一次 ES256 签名」，不再发邮件、不输验证码。

### 协议

| 步骤 | 接口 | body | 返回 |
|---|---|---|---|
| 1 注册 | `POST /api/v0/users/mfa/trusted_device/register` | `{mfa_ticket, mfa_public_key, mfa_algorithm:"ES256"}` | `{mfa_ticket(registerTicket), credential_id, mfa_challenge}` |
| 2 校验 | `POST /api/v0/users/mfa/trusted_device/verify` | `{mfa_ticket: registerTicket, mfa_signature}` | `{credential_id, expire_at}` |
| 3 登录 | `POST /api/v0/users/login` | `{email, mobile:"", area_code:"", password, device_id, os:"web", credential_id}` | `biz_code 13` + `{mfa_session_id, mfa_challenge}` |
| 4 签名 | `POST /api/v0/users/mfa/verify_signature` | `{mfa_session_id, mfa_signature}` | `biz_code 0` + `{user:{token,...}}` |

### 密钥与签名

- 曲线 **ECDSA P-256**，私钥 `extractable=false`（前端），公钥导出为 **SPKI DER 的 base64**（124 字符）。
- 签名输入 = `challenge + "\n" + (register 时 registerTicket / verify 时 mfa_session_id) + "\n" + credentialId + "\n" + action`，`action ∈ {"register","verify"}`。
- WebCrypto 输出 **64 字节 r||s（IEEE P1363）**，再标准 base64（88 字符）。
- Python 侧：`cryptography` 的 `key.sign(msg, ec.ECDSA(hashes.SHA256()))` 得到 DER，用 `decode_dss_signature` 拆 `r/s`，各 32 字节大端拼接后再 base64。

### 两套设备标识必须分开（关键）

| 位置 | 取值 | 原因 |
|---|---|---|
| `body.device_id` | `B<smid>`（89 字符，账号绑定设备） | 换成新 UUID 会返回 `biz_code 11 RISK_DEVICE_DETECTED` |
| `header x-device-id` | 注册受信设备时的 **UUID v4** | 服务端按它校验签名；用 `B<smid>` 会被降级成 `biz_code 4`（要求 OTP） |

`header x-device-model` 传空字符串。

### biz_code 对照

| 值 | 含义 |
|---|---|
| 0 | 成功（`user.token` 到手） |
| 11 | `RISK_DEVICE_DETECTED` — device_id 与账号绑定设备不符 |
| 13 | `MFA_CHALLENGE_REQUIRED` — 需 ES256 签名 |
| 14 | `MFA_VERIFICATION_CODE_REQUIRED` — 需邮箱验证码 |
| 4（verify_signature 返回） | 服务端不认签名，降级要求 OTP（多半是 `x-device-id` 用错） |

### 脚本

```powershell
.venv\Scripts\python.exe tools\sm_trusted_device.py   # 注册受信设备（一次性）
.venv\Scripts\python.exe tools\sm_trusted_login.py    # 免 MFA 登录 -> work\auth_token.enc
.venv\Scripts\python.exe tools\sm_check_device.py     # 三组对照探测（不发码，只诊断）
```
